# גיקלופדיה · תכנון תוכן

מערכת פרטית ומשותפת ללירן ולאלה לתכנון תוכן האינסטגרם של גיקלופדיה: לוח חודשי, תצוגת רשימה לנייד, בנק רעיונות, כרטיסי תוכן עם שקפים, קבצים והערות, ארכיון, וגיבוי ושחזור. הכול בעברית וב-RTL.

**הקמה וחיבור:** [docs/SETUP.md](docs/SETUP.md)

## ארכיטקטורה (שני רכיבים)

| רכיב | תפקיד | מסלול |
|---|---|---|
| **Supabase** | מסד נתונים (Postgres), התחברות, אחסון קבצים פרטי, עדכונים בזמן אמת | Free |
| **GitHub Pages** | אחסון האתר (קבצים סטטיים בלבד), בנייה אוטומטית ב-GitHub Actions | Free (מאגר ציבורי) |

- האתר הוא אפליקציית React סטטית שמדברת ישירות עם Supabase. אין שרת נוסף לתחזק.
- **ההרשאות נאכפות במסד הנתונים** (Row Level Security), ולא בממשק. כל טבלה וכל קובץ נגישים רק למשתמש מחובר שמופיע ברשימת `members`. טריגר במסד הנתונים חוסם יצירת משתמש שאינו ברשימה, וההרשמה הציבורית כבויה.
- **מניעת דריסה שקטה:** לכל כרטיס יש `version` שמנוהל בשרת. שמירה מותנית בגרסה שנטענה. אם מישהו אחר שמר בינתיים, השמירה לא מתבצעת ומוצגת הודעה. "רענון" משלב את השינויים: שדה ששונה רק אצלך נשמר, ובשדה ששניכם שיניתם הגרסה שלך מוצגת לצד העדכנית ואפשר לבחור ביניהן.
- **שמירה:** השמירה אוטומטית, בערך שנייה אחרי הפסקה בהקלדה. המסך מציג "שומר…", ורק אחרי שהשרת אישר מוצג "✓ נשמר בשרת". בכשל מוצגים "⚠ לא נשמר" וכפתור ניסיון חוזר. עד שהשרת מאשר, הטקסט נשמר גם ב-localStorage של המכשיר, ומשוחזר אם הדפדפן נסגר. localStorage משמש רק לשחזור טיוטות, ולא כמקור הנתונים.
- **קבצים:** נשמרים בדלי פרטי ב-Supabase Storage. הם נפתחים דרך קישורים חתומים שתקפים לשעה, ואין להם כתובת ציבורית. מגבלות הגודל והסוג נאכפות בשרת: עד 25MB לקובץ, ורק JPG, PNG, WEBP, GIF, HEIC, PDF, MP4, MOV ו-TXT.

## מגבלות המסלולים החינמיים ומה קורה בהגעה למכסה

נבדק בתיעוד הרשמי בנובמבר 2026: [Supabase pricing](https://supabase.com/pricing), [Supabase billing](https://supabase.com/docs/guides/platform/billing-on-supabase), [Supabase billing FAQ](https://supabase.com/docs/guides/platform/billing-faq), [Project pausing](https://supabase.com/docs/guides/platform/free-project-pausing), [Auth SMTP](https://supabase.com/docs/guides/auth/auth-smtp), [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

| משאב | מכסה חינמית | צפי לשימוש שלנו |
|---|---|---|
| מסד נתונים | 500MB | כרטיס טקסט שוקל כמה KB. אלפי כרטיסים תופסים כמה MB. |
| אחסון קבצים | **1GB בסך הכול** | **זו המגבלה שהכי סביר להגיע אליה.** כ-40 סרטונים של 25MB ממלאים אותה. כדאי לשמור קובצי וידאו גדולים ב-Drive ולהוסיף קישור בכרטיס. |
| גודל קובץ | 50MB בתוכנית; במערכת הגבלנו ל-25MB | — |
| תעבורה יוצאת | 5GB בחודש | צפייה בתמונות, הורדות וייצוא גיבויים. ייצוא מלא מוריד את כל הקבצים. |
| משתמשים | 50,000 בחודש | 2 |
| חיבורי זמן-אמת | 200 במקביל | 2–4 |
| השהיית פרויקט | אחרי שבוע ללא פעילות | ראו בהמשך |
| GitHub Pages | אתר עד 1GB, 100GB תעבורה בחודש (מגבלה רכה) | האתר שוקל כ-0.6MB |

**מה קורה בהגעה למכסה ב-Supabase Free:** אין חיוב. התוכנית החינמית לא מחייבת, ואין צורך להזין כרטיס אשראי. מקבלים התראה, ואם החריגה נמשכת, אחרי תקופת חסד השימוש במשאב שחרג נחסם עד תחילת מחזור החיוב הבא. לדוגמה, אחרי חריגה באחסון לא אפשר להעלות קבצים חדשים. הנתונים הקיימים לא נמחקים. כדי לפנות מקום מוחקים קבצים ישנים: מעבירים כרטיסים לארכיון ומוחקים לצמיתות, או מוחקים קבצים מתוך כרטיס. במערכת מוצגת במקרה כזה הודעה בעברית. **לא הופעל שום שירות בתשלום, ואין שום שדרוג אוטומטי.**

**השהיה:** פרויקט חינמי שלא היה בו שימוש שבוע מושהה, והאתר מציג "השרת לא זמין". לירן לוחץ **Restore project** בלוח הבקרה של Supabase. הנתונים נשמרים, ואפשר לשחזר עד שנה ממועד ההשהיה. כשמשתמשים במערכת באופן שוטף, ההשהיה לא קורית.

**מיילים:** שירות המייל המובנה של Supabase שולח רק לחברי הצוות בארגון ב-Supabase, ולכל היותר 2 מיילים בשעה. לכן המשתמשים נוצרים ידנית עם סיסמה, ואיפוס סיסמה נעשה ב-SQL לפי ההוראות ב-SETUP.md.

**GitHub:** GitHub Pages ו-GitHub Actions חינמיים במאגר ציבורי. הקוד ציבורי, אבל אין בו נתונים או סודות.

## גיבוי

במסך "גיבוי" מורידים קובץ zip שכולל את `backup.json` (כל הכרטיסים כולל ארכיון, שקפים, קישורים, הערות ופרטי קבצים) ואת תיקיית `files/` עם כל הקבצים המצורפים.

**לא כלול בגיבוי:** חשבונות המשתמשים והסיסמאות, הגדרות Supabase והאתר, וטיוטות שנשמרו רק בדפדפן ועדיין לא נשלחו לשרת. רשימת המשתמשים המורשים נכללת לעיון בלבד, ולא משוחזרת אוטומטית.

**שחזור** ממזג את הנתונים לפי מזהה ולא מוחק דבר. הוא מתבצע כפעולה אחת אטומית: אם משהו נכשל, אף כרטיס לא משתנה. בשחזור לפרויקט אחר, ההערות והיוצרים ממופים לפי כתובת האימייל.

## פיתוח ובדיקות

```bash
npm install
npx supabase start          # Supabase מקומי ב-Docker (סביבת בדיקה עם נתוני דוגמה בלבד)
npm run dev
```

הבדיקות רצות מול Supabase אמיתי. כברירת מחדל זה הפרויקט המקומי, לא הדמיה:

```bash
# הרשאות ומסד נתונים (API)
SB_URL=... SB_ANON=... LIRAN_EMAIL=... LIRAN_PASSWORD=... ELLA_EMAIL=... ELLA_PASSWORD=... \
  INTRUDER_EMAIL=... INTRUDER_PASSWORD=... node --test --test-force-exit tests/security.test.mjs

# קצה-לקצה בדפדפן (שני משתמשים, מחשב ונייד)
npm run build && npm run preview &
npx playwright test e2e --trace off

# ייצוא מסביבה אחת ושחזור לסביבה נפרדת
RESTORE_APP_URL=http://127.0.0.1:4174 E2E_SKIP_RESET=1 npx playwright test backup --trace off
```

> `tests/global-setup.ts` מוחק את כל הכרטיסים במסד הנתונים שהבדיקות מצביעות עליו. מריצים את הבדיקות **רק** מול סביבת בדיקה, לעולם לא מול הפרויקט האמיתי.
